# 学习设计模式库

> 这一份解决“怎么把内容排成关卡”，不涉及具体学科内容。

## 1. 步骤（step）的六种基本型

| 类型 | 一屏内容 | 用户动作 | 适合 |
|---|---|---|---|
| story | emoji + 标题 + 2–3 句话 + 可选图示 | 点“继续” | 建立直觉、过渡 |
| quiz | 题干 + 4 选项 + 解析 | 选择 | 检查理解 |
| read | 一个 section 标签 + 300–500 字卡片 | 继续/上一页 | 承载原文内容 |
| game | 目标 + 说明 + 可操作组件 + 提示 | 拖动/点击/输入 | 机制可视化、训练手感 |
| recap | 3–6 条要点 | 继续 | 关卡收尾 |
| final | 星级、XP、知识卡、下一关 | 点击 | 结算 |

组合原则：`story → game → quiz` 是最小教学单元；`read × N + quiz` 是资料关；`quiz × 10` 是测验关。

## 2. 关卡模式（可按主题自由组合）

### 2.1 概念关
适合“先解释一个抽象概念”。结构：
1. story：生活类比（1 个，不超过 3 句）
2. game：把类比变成可操作演示（滑块/开关/点击）
3. quiz：概念判断
4. story：边界情况/常见误解

### 2.2 实验关
适合“机制可参数化”的主题。结构：
1. story：要验证什么
2. game：可调参数 + 实时反馈 + 通关条件
3. quiz：解释现象
4. quiz：预测新参数下的结果

**设计要求**：给默认值、给目标、给“太强/太弱”的失败反馈、给再来一次。

### 2.3 资料关（承载原文的关）
适合“必须完整覆盖一份材料”。结构：
1. 导读：这是什么、多少张卡、怎么读、有什么检查点
2. N 张 read（每张一个知识点，带 section 标签）
3. 穿插 quiz（每 4–8 张一张，来自材料自带的题或自编）
4. 收尾：三句话总结
5. 术语/公式/误区/结论作为“附录卡”放在最后

覆盖要求：材料的每个核心章节至少 1 张卡；原文中的数字、公式、图表结论不能丢；卡片带定位（章节/页码）。

### 2.4 应用关（案例/论文）
结构：
1. 背景与问题（为什么值得做）
2. 方法关键（一张流程图 + 3 句话）
3. 证据（数字表：指标、基线、条件）
4. 边界（没证明什么）
5. 自测：3–5 题
适合把“一个真实案例”讲透，而不是罗列。

### 2.5 测验关 / BOSS
- 从各关抽题（默认每关 2 题），混合顺序；
- 答对阈值（如 80%）发证书；未过可重试；
- 解析必须给“为什么错”。

### 2.6 补课关（零基础必加）
材料本身有前置门槛时，单独开“补课层”：
- 从“函数是什么”级别开始，允许完全跳过；
- 每节 1–2 屏 + 1 题；
- 与主线解耦，随时可进。

## 3. 检查点节奏

- 每关 2–6 个检查点；资料关每 4–8 张卡一个；
- 紧跟在“刚讲完的知识”之后，不考没讲的；
- 答错不卡关：显示正确答案 + 解析，扣星但不阻止继续；
- 陷阱题（易混概念）单独设计，解析要长一点。

## 4. 难度与求助设计

三层求助，按顺序暴露：

1. **环境提示**：通关条件写在标题下（“损失 < 0.004”“误差 < 0.01”）。
2. **方向提示**：每个可调参数旁显示“↑调大/↓调小/✓刚好”，由数值梯度/误差实时计算。
3. **兜底演示**：一键“自动完成/演示”，看到正确过程，但不计入满星。

阈值原则：先跑一遍“人类可达性”测试——让不熟悉主题的人按提示操作，能在 3 分钟内过；否则放宽阈值或加提示。

## 5. 游戏化最小集

不要过度设计，够用即可：

- **进度**：关卡地图 + 每关步骤条；
- **XP**：每关固定 + 重玩给少量；总 XP 显示在顶栏；
- **星级**：按错误次数（0 错 3 星 / 1–2 错 2 星 / 其余 1 星）；
- **知识卡**：每关通关送一张“一句话卡片”，可在地图查看；
- **证书**：BOSS 通过后生成（含日期）；
- **存档**：localStorage，按课程分 key；可重置、可一键解锁；
- **音效/动画**：可选，默认关；彩带只在大节点用。

## 6. 术语与符号的“不空降”规则

1. 首次出现：给一句白话 + 读法（“θ 读 theta，是参数的统称”）。
2. 全局小抄：顶栏 📖，分组列出符号/术语/缩写。
3. 题目下方提示：“有符号不认识？点右上角 📖”。
4. 资料卡出现新符号时，用括号补一句解释或链接到小抄。

## 7. 微文案规范

- 每屏正文 ≤ 4 句；每句 ≤ 30 字；不写“众所周知”“显然”。
- 标题 6–14 字，包含动作或问题。
- 提示语写“怎么做”，不写“注意”。
- 解析格式：先结论（对/错在哪），再一句原因，可选一个反例。
- 失败文案不指责：给下一步动作。

## 8. 可访问性与移动端

- 按钮 ≥44px；对比度 ≥4.5:1；
- 所有交互可键盘完成（Tab/Enter/方向键）；
- 画布类交互提供按钮替代（“播放/重置/提示”）；
- 断网可用；不依赖外部字体；
- 手机竖屏可玩：单列布局，画布自适应宽度。


## 9. 学案（文档形态）的章节设计

学案不是“闯关卡片的拼接”，它要有自己的论证结构。每节推荐骨架：

1. **本节要解决什么**（1 段）：问题、为什么重要。
2. **直觉**（1 个类比 + 1 个具体例子）：先让人懂在说什么。
3. **定义/公式**：公式用公式卡呈现，逐符号解释 + 直觉 + 适用条件。
4. **展开**：推导/表格/对比/流程，长度按材料复杂度。
5. **边界与常见误解**：什么情况下不成立、最容易错在哪。
6. **自测**：2–3 题，带解析。
7. **对应闯关**：链接到练习该节的关卡。

章节长度：单节 800–2000 字；一个章节 3–8 节。整份学案按“序章 → 补课层 → 主体 → 工具层”组织：

- 序章：怎么用、学习地图、前置要求；
- 补课层：零基础需要的最小概念；
- 主体：按知识库走；
- 工具层：术语速查、公式手册、踩坑清单、动手实验、学习计划、综合自测、延伸资源、方法附录。

文档排版要求：固定侧栏目录、阅读进度、公式可以横向滚动、表格在窄屏可滚动、代码块带语言标记、提示框分色、打印时隐藏侧栏并展开折叠内容。
