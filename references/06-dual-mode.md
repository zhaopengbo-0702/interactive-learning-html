# 双形态同源设计：学案 + 闯关

> 目标：同一个学习主题，既有“完整教学逻辑”的长文档，又有“可视化、可操作、逐步推进”的闯关；两者由同一份知识库生成，互相引用，不打架。

## 1. 为什么必须双形态

学习任务有两种，缺一不可：

- **建立体系**：需要看全貌、推导、公式、表格、计划、来源、边界——这是**学案**擅长的。
- **维持注意与手感**：需要短反馈、动手、检查、进度感——这是**闯关**擅长的。

只做学案：容易变成“文字墙”，看不下去。
只做闯关：容易变成“小游戏合集”，学完没有体系。

双形态的正确关系：**学案是知识地图与依据，闯关是它的可执行版本。**

## 2. 单一事实源（library）

```text
library（学案章节/小节/块）
   ├─▶ study.html     直接排版成文档
   └─▶ game.html      小节 → 微卡片（自动切分 + 人工修整）
                      glossary / plan / tests 共用
```

规则：

1. 所有**文字、公式、数字、结论**只写在 `library`（以及 `glossary/plan/tests`）里；
2. `levels` 只允许写“教学编排”（顺序、提示、题目、交互参数），不重复知识正文；
3. 阅读步骤用 `sectionId` 引用 library，构建时自动切卡片；需要人工调整时用 `cardsOverride`；
4. 两件交付共享 `meta.chapters`（章节命名一致）。

## 3. 映射表

在数据里显式维护三列映射，交付前逐项核对：

| library 小节 | 学案锚点 | 闯关关卡 | 阅读卡 / 检查点 | 状态 |
|---|---|---|---|---|
| `ch1-s1` | `#ch1-s1` | `l1` | 2 卡 + 1 题 | ✅ |
| `ch2-s3` | `#ch2-s3` | `l3` | 3 卡 + 2 题 | ✅ |

`refs` 字段写法：

```jsonc
// library section
"refs": { "levels": ["l1"], "anchors": ["#ch1-s1"] }
// level
"refs": { "study": "ch1-s1" }
```

## 4. 双向链接规范

- URL 约定：`study.html#ch1-s1`、`game.html#/L1`（关卡 1 起）。
- 学案每节底部按钮：“去闯关练这一节 →”；
- 闯关：地图底部“打开完整学案”；阅读卡底部“查看本节完整学案 →”；通关页“回学案复习”。
- 在新标签页打开（`target="_blank"`），避免用户丢失当前进度。
- 链接目标文件不存在时，构建脚本要报错，不能静默生成死链。

## 5. 同一小节 → 两种表达

| 维度 | 学案 | 闯关阅读卡 |
|---|---|---|
| 长度 | 800–2000 字/节 | 300–500 字/卡 |
| 结构 | 小标题、完整推导、表格、公式卡 | 一个知识点/卡，公式就地解释 |
| 例子 | 可给多个，含边界情况 | 只留最能说明问题的 1 个 |
| 术语 | 首次出现解释，后文可简写 | 每卡独立可读，符号复用 glossary |
| 题目 | 节末自测（可多个） | 检查点（1 题/卡群） |
| 链接 | 指向对应关卡 | 指向完整学案小节 |

**切分规则**：标题开新卡；预算 300–500 字；引导句不拆；标题不落单；公式/表格/代码不跨卡。
**删减规则**：不删数字、不删公式、不删“边界/局限”，只压缩解释性文字与重复例子。

## 6. 术语与数字一致性

- `glossary` 是唯一术语源：学案术语表、闯关小抄、题目解析都从这里取。
- 关键数字字段化：例如 `metrics: { relL2: 0.00237, mape: 0.0087 }`，两件交付都用字段渲染，禁止手写两遍。
- 章节/小节/关卡 id 命名规范：`ch1`、`ch1-s1`、`l1`；id 不可复用、不可随意改（会断链）。
- 版本号写进 `meta.version`，两件交付页脚都显示。

## 7. 构建与版本

```powershell
python build.py             # dist/game.html
python build_study.py       # dist/study.html
```

- 两个脚本读同一份 `data.json`；共享模板只差壳；
- 输出文件名写进 `meta.gameFile/studyFile`，供交叉链接；
- 闯关进度 key（`storageKey`）与学案无关；学案不存进度（或只存阅读位置）；
- 内容大改时升 `storageKey` 主版本；id 变更要同步更新所有 `refs`。

## 8. 交叉一致性审计

除各自渲染审计外，必须跑：

1. **链接**：`game → study`、`study → game` 的每个链接目标文件存在且锚点存在；
2. **术语**：题目/卡片里出现的 glossary 术语，都能在 glossary 找到；
3. **数字**：同一指标在学案与闯关里的渲染值一致（由同一字段生成即天然一致；抽检渲染结果）；
4. **覆盖**：覆盖矩阵“必须项”在学案和闯关联赛都有去处；
5. **重复**：library 同一小节被多处引用时，闯关只引用不复制。

建议脚本输出：

```json
{
  "links": { "checked": 42, "broken": 0 },
  "glossary": { "missing": [] },
  "coverage": { "requiredTotal": 20, "covered": 20 },
  "version": { "study": "v1.0", "game": "v1.0", "match": true }
}
```

## 9. 常见反例

| 反例 | 后果 | 修法 |
|---|---|---|
| 学案与闯关各写一份正文 | 改一处忘一处，数字/术语漂移 | 以 library 为唯一源 |
| 学案只是把闯关卡片拼起来 | 没有体系、没有推导、不能查 | 学案按“节”组织，补推导/表格/计划 |
| 闯关只是学案翻页 | 没有可视化和手感 | 每个核心概念配 1 个可操作关 |
| 双向链接只做一个方向 | 用户回不去 | 强制双向 |
| 锚点 id 手写、拼错 | 死链 | 由数据字段生成锚点 |
| 关卡直接复制 library 大段 | 两份内容不同步 | 用 `sectionId` 引用 + 自动切卡 |
| 学案没有来源/边界 | 不可信 | 每节带定位、页脚写边界 |

## 10. 双形态验收清单

- [ ] library 的每个“必须”小节在学案有正文、在闯关有去处
- [ ] 两件交付术语表一致（同一个 glossary）
- [ ] 关键数字由同一字段渲染
- [ ] 双向链接全部可打开
- [ ] 学案可打印/可搜索；闯关可离线/可存档
- [ ] 两套渲染审计 + 交叉审计 0 问题
- [ ] README 同时说明两件交付怎么用、怎么改
