# 内容流水线：从原始材料到卡片与题目

> 这一份解决“怎么把材料自动/半自动切成可学习的数据”，并列出容易踩的坑。

## 1. 输入盘点

| 来源 | 提取方式 | 注意 |
|---|---|---|
| PDF（文本型） | pypdf / PyMuPDF 提取，保留页码标记 | 公式常被拆行；图页可能乱序 |
| PDF（扫描） | OCR（tesseract/paddle） | 标注可读性，公式易错 |
| Markdown / 纯文本 | 直接读 | 结构最稳 |
| HTML | lxml 解析，保留语义标签 | 注意脚本/样式节点 |
| Word/PPT | python-docx/python-pptx | 表格与图注要一起抽 |
| 代码库 | README + 关键源码 + 运行输出 | 需标注“是否真跑过” |

原则：**先转文本并保存中间产物**（`extracted/xxx.txt`），所有后续步骤可重跑。

## 2. 结构解析

1. 按标题层级切节（H1/H2/H3）。
2. 节内切“语块”（block）：段落、列表、表格、公式块、代码块、引用。
3. 语块是最小内容单位；卡片由语块组合而成。

语块切分必须识别：

- **代码围栏**（``` / ~~~）整块保留；
- **展示公式**（`$$...$$` / `\[...\]`）整块保留；
- **表格**（连续 `|` 行）整块保留；
- **列表**（连续列表项）整块保留；
- 行内公式 `` $...$ ``、行内代码 `` `...` `` 先保护再处理。

## 3. 卡片化（chunking）规则

目标：每张卡 300–500 字（含公式/代码的可放宽），一屏能读完。

规则：

1. 按预算合并语块；标题开启新卡。
2. **不拆“引导句 + 后续内容”**：如果当前卡最后一个语块以 `：`、`:`、`，`、`、`、`；`、`（`、`—` 结尾，不要在此换卡，把下一块并进来（除非超过预算 2.5 倍）。
3. **标题不落单**：标题必须和至少一个正文块同卡；如果标题因预算被切到卡尾，把它并到下一卡或把正文并进来。
4. 表格、代码、展示公式不跨卡拆开。
5. 卡片标签（label）取最近的标题；没有标题时用关卡名。
6. 每张卡记录来源定位（章节/页码），渲染在角标或卡片头部。

**验收**：随机抽 20 张卡，检查首尾是否完整；重点查“以冒号结尾的卡”与“以标点开头的卡”。

## 4. 数学公式处理

- 原始材料里公式格式千奇百怪：LaTeX、Unicode（`u_t`、`α`、`x²`）、Word 公式、图片。
- 先做**统一化**：把 Unicode 数学转成 LaTeX（下标 `u_t→u_{t}`、希腊字母 `θ→\theta`、上标 `x²→x^{2}`、简单函数式 `f(x)=3x+1` 整体包 `$...$`）。
- 转完必须**自检**：
  - 是否产生相邻 `$$`（会被当成展示公式分隔符）？→ 中间补空格或将相邻片段合并。
  - 是否把已有 `$...$` 二次包裹？→ 处理前先占位保护。
  - 是否生成空 `$$...$$`、未闭合 `$`？→ 审计脚本兜底。
- 渲染：优先内联 MathJax SVG（`tex-svg.js`），离线可用；CHTML 需要外部字体文件，不适合单文件交付。
- 中文放在 `\text{}` 里在 SVG 下通常可回退系统字体渲染；但能移到公式外的尽量移出。

## 5. 图片 / 代码 / 表格

- 图片：内联 base64（保证单文件）或相对路径 + 同目录打包；必须写 alt/图注。
- 代码：保留围栏语言标记；教程类内容要配“预期输出”和“常见报错”。
- 表格：宽表在移动端要能横向滚动；把关键行加粗/标色，便于扫读。

## 6. 题目生成

优先级：

1. 原来自带的练习题/思考题（改写成 4 选 1 + 解析）。
2. 从原文关键结论生成“判断/解释”题。
3. 自编应用题（给新条件，问会发生什么）。

题目要求：

- 4 个选项，干扰项要“像真的”（常见误解、方向反了、量级错了）；
- 答案唯一且有解析；解析解释“为什么错”而不只是“为什么对”；
- 题干含公式时，公式同样走公式统一化管线；
- 与所在卡片的知识点一一对应。

## 7. 覆盖矩阵

建一张表：

| 来源章节 | 核心知识点 | 去处（关卡/卡片） | 类型（必须/建议/可选） | 状态 |
|---|---|---|---|---|

交付前逐行打勾；“必须”项 100% 有去处。它是防止“内容缩水”的唯一硬约束。

## 8. 证据与来源标注

- 原文陈述：标章节/图表/页码；
- 作者声称：加“作者声称”标签；
- 你的解释/类比：加“解读”标签，不写成原文；
- 未核验的外部链接/版本：加“待核实”。
- 材料缺失（补充材料、图表读不清）要明确写“无法确认”，不要补造。

## 9. 常见坑

| 坑 | 症状 | 修法 |
|---|---|---|
| 直接按段落切卡 | 句子被切成两半，标点悬空 | 按语块切 + 引导句不拆 |
| 标题单独一卡 | 卡片只有标题 | 标题与正文同卡 |
| lxml/解析器只取元素不取文本 | 卡片开头/结尾丢字、丢序号 | 序列化时补 `element.text` 与 tail |
| 先转 Markdown 再保护公式 | 公式里的 `_`/`*` 被转成强调 | 先占位保护，再转换，再还原 |
| 代码围栏未识别 | 代码变成普通段落，还出现 `**` 等 | 解析器先识别 fence |
| 公式依赖 CDN | 断网/弱网公式变源码 | 内联 MathJax SVG |
| 卡片太长 | 一屏读不完 | 预算 300–500 字 + 强制分页 |
| 只有“读”没有“做” | 学完没反馈 | 每 4–8 卡插检查点 |


## 10. 双形态复用：library 是唯一源

- 学案正文、闯关阅读卡、工具书关、自测题，全部从 `library + glossary + plan + tests` 派生；
- 学案按“节”排版；闯关按 300–500 字切卡片（规则见第 3 节）；两者不各写一份正文；
- 关卡数据里只写“教学编排”（提示、题目、交互参数），正文用 `sectionId` 引用；
- 内容要改时只改 library，然后重建两件交付并跑两套审计。
