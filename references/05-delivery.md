# 交付、说明与维护

## 1. 交付物清单

最小：

1. `course.html`（单文件，可双击）；
2. `README.md`（怎么用、怎么改、内容边界）；
3. 审计记录（可放 README 或单独文件）。

推荐追加：

- 数据源文件 `course.json` + `build_data.py` + `build.py`（可重建）；
- 审计脚本（`audit_deep.py`、`audit_interaction.js`）；
- 原始材料（PDF/文档）或链接索引；
- 演示截图 2–3 张（放 README，方便预览）。

## 2. README 模板

```markdown
# 课程名

## 打开哪个文件？
- `course.html`：主文件，双击打开
- `README.md`：本说明

## 里面有什么
| 章节 | 关卡 | 内容 |
|---|---|---|

## 怎么用
- 线性解锁 / 一键解锁
- 进度保存在浏览器；重置入口
- 公式离线渲染，无需联网

## 质量自检
- 全量渲染：N 步，0 报错
- 公式：0 未渲染
- 文本：0 问题
- 交互：全部通关
- 离线：通过

## 内容来源与边界
- 来源材料与版本
- 「原文/声称/解读/待核实」说明
- 未核验项
```

## 3. 发布前检查

- [ ] 双击打开，主流程可走通（首关→通关→证书）
- [ ] 手机宽度（375px）无横向滚动、按钮可点
- [ ] 断网打开，文字与公式正常
- [ ] 历史进度不串版本（不同 storageKey）
- [ ] 外部链接标注“未核验”
- [ ] 审计记录齐全

## 4. 版本策略

- 内容大改 → 升 `storageKey` 主版本，提示用户重置；
- 只修 bug → 保持 key，避免进度丢失；
- 精简版/完整版并存 → 两个文件、两个 key，README 说明区别；
- 文件命名带版本或日期，避免“最终版_final_v2”混乱。

## 5. 维护

- 内容更新走“改数据 → 重建 → 重跑 L2–L5 审计”；
- 引擎更新后跑全量审计 + 交互审计，再看手机截图；
- 保留一份“修改日志”，记录修了什么、怎么验证的。

## 6. 边界与合规

- 引用材料要标来源；大段原文引用注意版权，必要时只做“摘要 + 定位 + 少量引用”；
- 论文/教材的结论区分“作者声称”和“已核实”；
- 外部工具版本、许可证、链接，未实际核验就标注“待核实”；
- 不要承诺“学会”这类效果，写清楚适用范围和前置要求。


## 7. 双形态交付物

| 文件 | 用途 |
|---|---|
| `study.html` | 完整学案（长文、可打印、可搜索） |
| `game.html` | 闯关（互动、存档、证书） |
| `README.md` | 两件怎么用、怎么改、内容边界 |
| `audit-study.md` / `audit-game.md` | 两套渲染审计 + 交叉一致性审计记录 |
| `data.json` + `build*.py` + 审计脚本 | 可维护 |

README 中必须说明：两份文件如何互相跳转、进度存在哪个 key、离线是否可用、内容来源与未核验项。
